# Qwen3.5 GPTQ to Qwen2.5-Coder AWQ Rollback Plan

> **For Hermes:** This is a plan-only rollback runbook. Do not execute production changes without explicit approval.

**Goal:** Safely roll back the Salt-managed `rdt-llm` vLLM lane in `red-dragon-tech/redsalt-master` from `qwen3.5-35b-a3b-gptq-int4` to the previous `qwen2.5-coder-32b-awq` served model.

**Architecture:** Change desired state in `dev`, validate and review it, promote the reviewed commit to `prd`, then let/signal the Salt master sync to apply `prd`. Gate the live apply with `state.show_highstate` and `state.apply test=True`, then verify the OpenAI-compatible endpoint with `/v1/models` and native tool-call smoke tests.

**Tech Stack:** SaltStack, redsalt-master, vLLM Docker/OpenAI server, Caddy reverse proxy, GitHub `dev` → `prd` promotion workflow.

## Risks and mitigations

- **Risk: stale validators keep demanding Qwen3.5.** Mitigation: update `scripts/validate.py` and tests in the same PR as the pillar rollback.
- **Risk: Qwen2.5 64k context/CPU-offload tuning is slower but previously required for fit/stability.** Mitigation: keep the known previous `--cpu-offload-gb 8`, `--enforce-eager`, `--kv-cache-dtype fp8`, and Yarn override unless a separate validated performance change is requested.
- **Risk: systemd reports active while Docker/vLLM is unhealthy.** Mitigation: verify Docker status, `/v1/models`, direct completions, and recent logs.
- **Risk: clients still request the Qwen3.5 served name.** Mitigation: update Hermes provider model only after `/v1/models` proves Qwen2.5 is live.
- **Risk: unsafe production shortcut.** Mitigation: no force push; use PR to `dev`, reviewed promotion to `prd`, `state.show_highstate`, `state.apply test=True`, then live `state.apply`.
- **Risk: secret exposure during diagnosis.** Mitigation: use presence/status checks only; do not print token-bearing env files, Caddy auth snippets, or full sensitive configs.

## Stop conditions

Stop and do not proceed to live apply if any of these occur:

- PR is not reviewed/approved and no explicit emergency approval exists.
- `python3 scripts/validate.py` fails.
- tests fail.
- Salt master is not on the intended `prd` SHA.
- `state.show_highstate` fails.
- `state.apply test=True` fails.
- Highstate preview includes unrelated destructive changes.
- `/v1/models` remains unavailable after apply and logs indicate model load/startup failure with no clear safe forward fix.

## Recovery if rollback apply fails

1. Do not make further production changes blindly.
2. Capture concise failure summaries from Salt state return, Docker status, `/v1/models`, and recent vLLM logs.
3. If the AWQ model cannot load, revert the rollback commit in `dev`, repeat review/promotion to `prd`, sync the Salt master, rerun `state.show_highstate` and `state.apply test=True`, then apply the forward revert only after gates pass.
4. Keep provider config aligned with whichever model `/v1/models` actually reports healthy.
